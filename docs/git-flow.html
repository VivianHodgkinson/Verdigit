Releasing Verdigit with Git Flow

Everything here happens in Verdigit, except publishing on GitHub. Tick steps off as you go.

feature/… → develop → release/X.Y.Z → main + tag vX.Y.Z → GitHub draft → Publish

0 One-time check

Already done for this repo. Just confirm it if a tag ever comes out wrong.

Why it matters: without the prefix the tag is 0.2.6 instead of v0.2.6, and GitHub Actions only builds tags that start with v.

For each change. Nothing gets released here; it just lands on develop.

When develop has everything you want to ship.

(updates the steps below)

  3. Older Verdigit (0.2.5 and earlier) doesn't have the tick box. Click Terminal, run the command below, then stage both files and commit them as Release 0.2.6.

3 Publish on GitHub

The tag push starts the build automatically.

Note: installed copies only see published releases. Until you click Publish, nobody gets the update.

? If something looks off

The tag has no v at the frontThe version tag prefix is blank. See the one-time check. Delete the bad tag (right-click it under Tags) and recreate it as vX.Y.Z on main with the push option ticked.
The build ran but no draft appearedThe tag doesn't start with v, or it was never pushed. Check Tags in the sidebar and on GitHub.
The installed app updates but shows the old version numberThe version update was unticked or skipped, so package.json still has the old number. Check for the Bump version commit.
Finish Release stops with a merge conflictResolve the files in the right-hand panel, commit, then run Finish Release again.
Actions jobs fail within secondsUsually a GitHub billing or account lock, not the code. Check the job log.
